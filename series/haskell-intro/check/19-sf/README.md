# check/19-sf

**記事には載せない。** ストリーム関数のアローを検討したときの記録
（19-PLAN 決定事項 2 で本文から除外）。`runghc` で動く。

```hs
newtype SF b c = SF { runSF :: [b] -> [c] }
```

入力の列を出力の列に変える計算。`delay` で 1 つ前の値を持ち越せるので、
時間方向の処理（FRP）がそのまま書ける。Hughes のチュートリアル以来の定番の題材で、
Yampa のストリーム関数もこの形。

|ファイル|内容|
|---|---|
|`SF.hs`|`Category`・`Arrow`・`ArrowLoop` のインスタンス、`delay`、`rec` を使ったカウンター|

```text:SF.hs
[0,2,3]
[(2,2),(3,4),(4,6)]
[0,1,0,1,2]
```

3 行目が `rec` を使ったカウンター。`reset` が `True` の位置で 0 に戻る。

## 本文から外した理由

- 面白い例（カウンターのようなフィードバック）に `rec` と `ArrowLoop` が要る。
- `loop` の実装が遅延評価の理解を前提にする
  （`stream ~(x:xs) = x : stream xs` の遅延パターン）。
- 19 回の主題は「合成した時点で形が決まる」ことなので、
  静的パーサ（`check/19-parser/`）の方が直接的。

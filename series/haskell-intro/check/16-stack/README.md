# check/16-stack

16 回 練習【問3】【問4】スタックマシン DSL の検証コード。`runghc` で動く。

|ファイル|内容|
|---|---|
|`Stack.hs`|`StackF`・`push`・`pop`・`calc`（問3）と `runStack`（問4）。`Free` の定義を先頭に補ってある|

## 実行結果

```text
7
```

`calc` は 3 と 4 を積み、2 つ取り出して足し、積み直して最後に取り出す。

## 確認したこと

- `Pop (Int -> next)` は本文のテレタイプ `GetLine (String -> next)` と同じ形。
  `pop = liftF (Pop id)` で `Stack Int` になり、`a <- pop` で受け取れる。
  **本文で解説した「続きが関数の命令」を、読者が別の題材に当てはめる練習になっている。**
- `runStack` はスタックを第 1 引数で持ち回る。`runPure`（残りの入力を持ち回る）と
  骨組みが同じで、`Pure` まで来たときにリストではなく手順書の結果 `a` を返す点が違う。
- 空のスタックに `Pop` が来たときは 0 を返す（テレタイプで入力が尽きたら空文字列を
  返したのと同じ流儀）。
- 09 回「状態系モナド」`## アクションの定義` の `getch`（`x:xs <- get; put xs; return x`）が
  `pop` とほぼ同じものだが、**記事では触れていない**（State との対比を差し込むのが
  無理やりだったため。16-PLAN 変更点 13 を参照）。
- 言語拡張は `DeriveFunctor` のみ。`runghc -XHaskell2010 Stack.hs` で確認すると
  `deriving Functor` だけがエラーになる（GHC2021 では既定で有効）。

## 17 回との関係

同じスタックマシンを Operational モナドで書き直すと、Free との違い（`Functor`
インスタンスが要らない・GADTs で命令を列挙する）が同じ題材の差分として見える。
ジェネレーターを 13 回（継続）と 16 回（Free）で作り直したのと同じ構図。

## 記事の狙い

**ゴールは「計算の形を先に固定する」。**

16〜18 回は、命令をデータとして組み立てて後から解釈する、という道具立てを追ってきた。
19 回は同じ「実行前に中身が分かる」という利益を、**まったく別の方法**で得る。
命令をデータにするのではなく、**合成の形そのものを型にして、値への依存を断つ。**

モナドの `>>=` は、次の計算を**値から選べる**。この自由さのせいで、実行してみるまで
何が起きるか分からない。アローは `>>=` を持たないので次の計算を値から選べず、
代わりに**合成した時点で全体の形が決まる。** だから実行前に調べられる。

### この回の一行の主張

**`>>=` が書けないことが、アローの取り柄になる。**

|モナド|アロー|
|---|---|
|`a -> m b`（Kleisli）。関数の戻り値としてモナドを返す|`a b c`。入力から出力への計算そのものを型にする|
|次の計算を値から選べる（動的）|形は組み立てた時点で決まる（静的）|
|中身は実行しないと分からない|実行前に調べられる（本文の `expects`）|
|`>>=` / `>=>`|`>>>` / `&&&` / `***`|
|`do`|`proc`|
|—|`ArrowApply`（`app`）を足すとモナドと同じ表現力になり、静的な利点が消える|

### 16〜18 回との関係（この回の位置づけ）

**同じ目的地に、4 通りの道がある**という並べ方をする。

|回|中を見られるようにする方法|
|---|---|
|16（Free）|命令を木のデータにして、後から辿る|
|17（Operational）|継続を `>>=` の側に出し、命令を GADT で並べる|
|18（Eff）|命令の型をリストにして複数の効果を混ぜる|
|**19（アロー）**|**合成の形を型に固定し、値への依存を断つ**|

- 16〜18 回は「`>>=` に意味を与えない」ことで組み立てと解釈を分けた。
  19 回は「`>>=` を持たない」ことで同じ利益を得る。**同じ主題の別解として並べられる。**
- ⚠ ただし**アローは Free の代わりではない。** 手順書を後から複数のインタープリターで
  解釈する、という使い方はしない。得られるのは「実行前に静的な情報を取り出せる」ことと
  「値に依存しない配線を型で保証できる」ことに限られる。誇張しない（17 回の
  「Free との優劣を煽らない」と同じ姿勢）。

### 記事の導入文（案・PREFACES.md 用）

> Haskell ではモナドと呼ばれる部品を組み合わせてプログラムを作りますが、**アロー**は
> 入力から出力への計算そのものを型として扱い、関数合成を一般化した枠組みです。
> モナドと違って次の計算を値から選べない代わりに、組み立てた時点で計算の形が決まります。

## 構成案

### 1. `# 関数合成を一般化する`（入口）

- **入口は 01・04 回の関数合成 `.`。** `f . g` を左から右に書き直した `>>>` を出す。
- `Category` クラス（`id`・`.`）。`Control.Category` を import すると Prelude の
  `id`・`.` と衝突するので `import Prelude hiding ((.), id)` が要る、という実務的な注意。
- **`Kleisli` を並べる。** `a -> m b` も `>>>` でつなげる。
  **15 回の `>=>`（モナド則を書き直した節）と同じもの**であることを見せる
  👉[モナドとゆかいな仲間たち](URL#>=>-で書き直す)
  - ここでユーザーの 2015 年の記事「アローの取っ掛かり」と同じ入口を通ることになるが、
    **本文からはリンクしない**（下記「既存記事との関係」）。
- ⚠ この節では「アローとは何か」をまだ定義しない。
  **「関数もモナドの関数も、同じ形で合成できる」という観察だけで 1 節を持たせる。**

### 2. `# アローの部品`

- `arr`・`first`・`second`・`***`・`&&&`。**関数アロー（`(->)` のインスタンス）で動かす。**
- **タプルが配線になる**という見方。図（mermaid）を 1 つ置く。
  `&&&` は分岐、`***` は 2 本を並べる、`first` は片方だけ通す。
- 平均を求める例（検証済み）。

  ```hs
  mean :: [Double] -> Double
  mean = (sum &&& (fromIntegral . length)) >>> uncurry (/)
  ```

- **`arr` は「ただの関数をアローに持ち上げる」**。16 回の `liftF`・17 回の `singleton` と
  同じ「持ち上げ」の位置にある、という繋ぎ方ができる。
- 【練習1】配線を組む。

### 3. `# proc 記法`

- `{-# LANGUAGE Arrows #-}` と `proc x -> do y <- f -< x`。
- **`do` との対比。** `<-` の右が「アロー `-<` 入力」になる。
- **シリーズ初の「構文のための言語拡張」。** 3 段の対比が作れる。

  |回|拡張|種類|
  |---|---|---|
  |16|`DeriveFunctor`|便利のため（書かなくても済む）|
  |17|`GADTs`|表現力のため（書けないものが書ける）|
  |**19**|**`Arrows`**|**構文のため（書き方が変わる）**|

- ⚠ **言語拡張の書き方への 👉リンクは張らない**（17-PLAN 推敲時の変更点 2 のユーザー判断）。
- 【練習2】練習1 を proc で書き直す。

### 4. `# アローを自作する`（★見せ場の前半）

静的パーサ `P`。**`runghc` だけで動く**（検証済み）。

```hs
newtype P b c = P ([Char], [Char] -> b -> Maybe (c, [Char]))
```

- **タプルの左が静的な情報**（このパーサが受け付ける文字）、右が実際の解析。
- `instance Category P` の `.` で**静的な情報を連結する**のが要点。
  合成した時点で `t1 ++ t2` が確定する。
- `char`・`expects`・`runP`。

  ```
  > expects (char 'a' >>> char 'b' >>> char 'c')
  "abc"          -- 実行する前に分かる
  ```

- 12 回のパーサコンビネータと繋ぐ。あちらは `>>=` でつないだので、
  何を受け付けるかは実行してみないと分からなかった。
- 【練習3】`string` を足す、または選択を足す（題材は下記「練習」）。

### 5. `# 分岐`

- `ArrowChoice`（`left`・`|||`・`+++`）と、proc の中の `if`。
  **proc で `if` を書くと `ArrowChoice` が要る**（検証済み。エラーで気付ける）。
- **分岐しても静的な情報は取れる。** 両方の枝の和になる（検証済み。`expects q` が `"ab"`）。
  値がどちらに転んでも、**起こりうることの全体は事前に分かる。**

### 6. `# モナドにはできない`（★この回の見せ場）

**順序は「詰まり → `app`」**（決定事項 9）。

- **`>>=` を書こうとすると詰まる。** `bindP :: P b c -> (c -> P b d) -> P b d` の
  静的な情報を作るには `k` を適用した結果が要るが、そのためには解析結果 `c` が要る。
  **`c` は実行しないと手に入らない。** 型を書き下して散文で詰まらせる（型穴は使わない）。
- **`ArrowApply`（`app`）を足すとモナドと同じ**になる。**実装はできてしまい、
  そのとき `expects` が嘘になる**（検証済み）。`Kleisli` は `app` を持つ。
  **アローの利点は「持たないこと」から来ている。**
- ⚠ **「書けない」ではなく「書くと静的な情報が嘘になる」**と書く
  （上記「「モナドにはできない」の裏取り」）。
- 15 回の階層（`Functor` → `Applicative` → `Monad`）の横に置く地図を 1 つ描く。
  **`Applicative` が静的、`Monad` が動的、アローはその間**という位置づけ。
  ⚠ ここは踏み込みすぎない。理論の言葉（`Applicative` とアローの対応関係）には入らない。
- 【練習4】要検討（下記「練習」）。

### 7. `# アローの現在`

**実用頻度を偽らない。**

- `Control.Arrow` は base 同梱。**`&&&`・`***`・`first`・`second` は
  アローの文脈と関係なく普通に使われている**（決定事項 7）。
  読者がすでに見たことがある可能性が高い演算子なので、ここで回収する。
- 実際にアローとして使われている領域は限られる。
  - FRP: Yampa（lts-24 に 0.15 で収録。検証済み）。ストリーム関数がそのままアロー。
  - SQL: opaleye（lts-24 に 0.10.8.0 で収録。検証済み）。クエリを実行前に組み立てる、
    という**まさに静的な用途**。
  - かつての HXT（XML）。⚠ 現況は要確認（TODO）。
  - **コードは載せない**（決定事項 12）。名前と用途だけ。
- **Profunctor に 1 段落**（決定事項 10）。`first`・`***` にあたる操作が
  現代では `Profunctor`・`Strong`・`Choice` の語彙で語られる、という位置づけだけ。
  定義にも法則にも立ち入らず、「アローは古い」という書き方もしない。

## 検証済みの事実（2026-08-11）

**すべて実際に動かして確認した。** 環境は GHC 9.6.6（システム）、`runghc` のみ。
外部パッケージは使っていない。

### 言語拡張

- **`Arrows` は GHC2021 に含まれない。** pragma を外すと
  `parse error on input ‘->’` になる（`proc x -> do` の行）。
- **`Arrows` 以外は何も要らない。** 静的パーサ（`Category`・`Arrow`・`ArrowChoice` の
  インスタンスを自作、`proc` の `if` つき）を **`runghc -XHaskell2010` で実行しても
  通った**（pragma は `Arrows` のみ）。
  **`FlexibleInstances` も `RankNTypes` も不要。**
  → 掲載コードに載る pragma は `{-# LANGUAGE Arrows #-}` 1 行だけになる。

### base の API

- `Arrow` のスーパークラスは `Category`（`Control.Category`）。
  `Control.Arrow` が `>>>`・`<<<` を再エクスポートするので、
  **使うだけなら `Control.Category` を import しなくてよい。**
  自作の `instance Category` を書くときだけ import が要り、Prelude と衝突する。
- 動作確認した演算子: `arr`・`first`・`second`・`***`・`&&&`・`>>>`・
  `|||`（`ArrowChoice`）・`app`（`ArrowApply`）・`returnA`。
- **`Kleisli` の `>>>` は `>=>` と同じ結果**（`Kleisli f >>> Kleisli g` と `f >=> g` を
  `Maybe` で比較して一致）。
- **`Kleisli IO` は `app` を持つ**（`runKleisli app (Kleisli (return . (+1)), 5)` → `6`）。
  モナドから作ったアローは `ArrowApply` になる、という主張の裏。

### 静的パーサ（本文の題材）

```hs
newtype P b c = P ([Char], [Char] -> b -> Maybe (c, [Char]))
```

`Category`・`Arrow`・`ArrowChoice` のインスタンスを自作して動作確認済み。

|確認したこと|結果|
|---|---|
|`expects (char 'a' >>> char 'b' >>> char 'c')`|`"abc"`（**実行前に取れる**）|
|`runP p "abcd" ()`|`Just ((),"d")`|
|proc の `if` で分岐した `q` の `expects`|`"ab"`（**両方の枝の和**）|
|`runP q "ab" True` / `False`|`Just ((),"b")` / `Nothing`|

### 「モナドにはできない」の裏取り（構成案 6）

**2 通りの見せ方をどちらも実装して確かめた**（`check/19-parser/`）。

1. **`>>=` にあたる関数を書こうとすると型穴で詰まる**（`Bind.hs`。意図的に
   コンパイルが通らないファイル）。

   ```hs
   bindP :: P b c -> (c -> P b d) -> P b d
   bindP (P (t1, f)) k = P (t1 ++ expects (k _), \s b -> Nothing)
   ```

   ```text
   error: [GHC-88464]
       • Found hole: _ :: c
   ```

   **静的な情報を組み立てるには `k` を適用する必要があり、そのためには解析結果 `c` が要る。
   しかし `c` は実行してみないと手に入らない。** 組み立て時に確定できるものと
   実行時にしか手に入らないものの境界が、そのままエラーとして出る。

2. **`ArrowApply` は実装できてしまう**（`Apply.hs`）。実行時に受け取ったパーサを走らせるので
   静的な情報を空にするしかなく、**`expects` が嘘になる**（`""` と答えるのに `'a'` を消費する）。

- ⚠ **したがって「モナドにはできない」は「書けない」ではなく
  「書くと静的な情報が嘘になる」が正確。** 型エラーとして機械的に出るのは 1 の形だけで、
  それも型穴を使って詰まりを見せた場合に限る。**本文の言い方に反映すること。**

## 執筆時の変更点

1. **1 節の自作 `Category` インスタンスを、関係の圏から一点圏（モノイド）へ変更**
   （2026-08-13。決定事項 12 を覆す）。
   関係の圏 `newtype Rel a b = Rel (a -> b -> Bool)` は **`Category` のインスタンスに
   できない。** `id = Rel (==)` に `Eq a`、合成の全探索に `Bounded b`・`Enum b` が
   必要になるが、`Category` のメソッドには型クラス制約を足せないため。
   検証で GHC のエラーを確認済み（`check/20-category/README.md`）。

   代わりにモノイドを「対象が 1 つの圏」とみなす。

   ```hs
   newtype Mon m a b = Mon m deriving (Show, Eq)

   instance Monoid m => Category (Mon m) where
       id = Mon mempty
       Mon g . Mon f = Mon (f <> g)
   ```

   - **射がモノイドの要素で、関数ですらない。** 「`id` は恒等関数ではなく単位元」という
     19 回 `### 単位元` の指摘が、関係の圏より一段はっきりする。
   - **14 回の `Monoid` と直結し、5 節「モナドはモノイド対象」への布石になる。**
     1 節で「モノイドは圏の特別な場合」を見せ、5 節で「モナドは圏のモノイド」を見せる
     という往復ができる。
   - ⚠ **対象が 1 つであることは型では強制できない。** `a`・`b` は使われない型引数
     （phantom）なので、`Mon [String] () ()` のように `()` へ固定して「そう見なす」
     という約束になる。**本文でこの点を明示する。**
   - 節名は `## 関係の圏` から `## 一点圏` へ。
2. **4 節の具体例を `step n = [n + 1, n * 2]` に確定**（決定事項 13 の未決部分）。

   `1 + 1` と `1 * 2` が衝突して `[2,2]` になり、分岐が見えないため）。

### 1. `# 圏`

- **入口は 19 回の `Category`。** `class Category cat where id :: cat a a;
  (.) :: cat b c -> cat a b -> cat a c` を再掲し、これが圏の定義そのものだと明かす。
  - 型 `a`・`b`・`c` が**対象**、`cat a b` が**射**、`.` が**合成**、`id` が**単位元**（恒等射）。
  - 19 回の `### 単位元` で「`id` に求められているのは恒等関数であることではなく
    単位元であること」と説明済み。**ここが最大の足場。**
- **公理は 2 つだけ**（結合律・単位律）。19 回で `id >>> f = f`・`f >>> id = f` を書いた。
  結合律 `(f >>> g) >>> h = f >>> (g >>> h)` を足す。
- **`## Hask 圏`**: 型を対象、関数を射とみなす圏。`instance Category (->)` がそれ。
- **`## bottom`**（決定事項 7）: すべての型が `undefined`・非停止を要素に持つので、
  Hask を厳密に圏として扱うと壊れる。`seq` があるとファンクター則・自然性が破れる。
  - 具体例をコードで示す（検証項目）。避けて通らない。
  - ⚠ **ここで読者を突き放さない。** 「だから圏論は使えない」ではなく、
    「bottom を無視すれば対応が取れる」という実務的な着地にする。
- **`## 一点圏`**: 新規コードとして `instance Category` を 1 つ自作する
  （「執筆時の変更点」1 で決定事項 12 を差し替え。19 回は静的パーサー `P` なので別題材）。

  ```hs
  newtype Mon m a b = Mon m deriving (Show, Eq)

  instance Monoid m => Category (Mon m) where
      id = Mon mempty
      Mon g . Mon f = Mon (f <> g)
  ```

  - **モノイドを「対象が 1 つの圏」とみなす。** 射はモノイドの要素、合成は `<>`、
    単位元は `mempty`。
  - **射が関数でない例**になるのが選んだ理由。19 回 `### 単位元` の
    「`id` に求められているのは恒等関数であることではなく単位元であること」が
    ここで一段はっきりする。
  - **5 節への布石。** 1 節で「モノイドは圏の特別な場合」、5 節で「モナドは圏のモノイド」。
  - ⚠ 対象が 1 つであることは phantom 型では強制できないので、`()` に固定して
    「そう見なす」約束であることを本文で断る。

### 2. `# 関手`

- **入口は 15 回の `Functor`。** 関手は 2 つの対応の組であることを明かす。
  - **対象の対応**: 型 `a` を型 `f a` に移す（`f :: * -> *`。種は 14・16 回で既習）。
  - **射の対応**: 関数 `a -> b` を `f a -> f b` に移す（`fmap`）。
  - **`Functor` インスタンスは、この 2 つを 1 つの型構築子で兼ねている。**
    型構築子の適用が対象の対応、`fmap` が射の対応。
- **ファンクター則が「構造を保つ」の中身。** 15 回 `## ファンクター則` は
  `fmap id == id`・`fmap (f . g) == fmap f . fmap g` を「単位元」「準同型」と
  呼んでおり、`:::message` で「`fmap` は関数合成という構造を保つ準同型」とまで書いてある。
  **圏論の言葉では、合成と恒等射を保つことが関手の定義。**
- **`## 自己関手`**: Hask から Hask への関手なので**自己**（endo）関手。
  `f :: * -> *` で型が閉じているのがその現れ。**5 節の「自己関手の圏」への布石。**

### 3. `# 自然変換`

- **入口は 16 回の `foldFree`・18 回のハンドラー。** どちらも
  `forall a. f a -> g a` の形をしていた。

  ```hs
  type f ~> g = forall a. f a -> g a
  ```

- 実例を base から拾う: `listToMaybe :: [] ~> Maybe`・`maybeToList :: Maybe ~> []`・
  `Just :: Identity ~> Maybe`（または `reverse` が `[] ~> []` になること）。
- **`## 自然性`**: 自然性条件を等式で書き、実際に両辺を評価して一致を見せる。

  ```hs
  fmap h . alpha == alpha . fmap h
  ```

  「先に中身を書き換えてから容れ物を移しても、容れ物を移してから中身を書き換えても同じ」。
  - **四角形の可換図式を描く**（決定事項 2。図を使うことが確定している箇所）。
    4 つの頂点 `f a`・`f b`・`g a`・`g b` を `fmap h`・`alpha` の 4 本の辺で結び、
    **どちらの経路を通っても同じ**という形を示す。等式と図が同じことを言っていると
    分かる箇所なので、ここに使う。
- **`:::message` でパラメトリシティ。** Haskell では `forall a.` の形をした関数は
  自然性条件を自動的に満たす（bottom を除く）。型だけから等式が出るという話で、
  README.md「未定のアイデア」のパラメトリシティの項目にあたる。**深入りしない。**
- ⚠ **`~>` は自作する**（決定事項 3）。`TypeOperators` の要否は検証項目。

### 4. `# Kleisli 圏`

- **19 回で書いた `instance Monad m => Category (Kleisli m)` が Kleisli 圏そのもの。**
  対象は Hask と同じ型、射は `a -> m b`、合成は `>=>`、恒等射は `return`。
- **15 回 `### >=> で書き直す` が圏の公理そのものだったことを明かす。**
  あの節はモナド則を次の 3 本に書き直して「`>=>` を掛け算だと思えば `return` は 1」
  と締めている。

  ```hs
  return >=> f    == f                -- 左単位元
  f >=> return    == f                -- 右単位元
  (f >=> g) >=> h == f >=> (g >=> h)  -- 結合法則
  ```

  **これは 1 節で書いた圏の公理（結合律・単位律）と同じ形。**
  つまり**モナド則とは「Kleisli 圏が圏であること」**の要求だった。
- **動作確認はリスト（非決定性計算）**（決定事項 13。19 回は `parse`／`half` の `Maybe`）。
  `a -> [b]` の形の射を `>=>` でつなぎ、結合律と単位律を実際に評価して見せる。
  合成の結果が展開先のリストとして目に見えるのが利点。非決定性計算という語は
  17・19 回で既出なので、そのまま引き継ぐ。
- ⚠ この節は**分量を抑える。** 19 回と 15 回の再確認が主で、新出は「Kleisli 圏」という
  名前だけ。5 節への助走として短く通す。

### 5. `# モナドはモノイド対象`（★見せ場）

**「モナドは自己関手の圏におけるモノイド対象である」という有名な一文を、
語ごとに分解して回収する。**

- **`## join`**: `>>=` の代わりに `join :: m (m a) -> m a` を主役に据える。
  `>>=` と `join` が相互に定義できることをコードで示す（検証項目）。

  ```hs
  m >>= k  = join (fmap k m)
  join mm  = mm >>= id
  ```

- **`## μ と η`**: `join` と `return` を**自然変換として**読み直す。
  - `join :: m . m ~> m`（μ）
  - `return :: Identity ~> m`（η）
  - 関手を掛け算のように並べた `m . m` が「2 つ重ねた `m`」にあたること、
    `Identity` が単位元の位置にあることを説明する。
- **`## モノイド則`**: 14 回の `Monoid`（`<>` と `mempty`、結合律と単位律）と並べる。

  |`Monoid`|モナド|
  |---|---|
  |`<>  :: a -> a -> a`|`join   :: m (m a) -> m a`|
  |`mempty :: a`|`return :: a -> m a`|
  |`(x <> y) <> z == x <> (y <> z)`|`join . join == join . fmap join`|
  |`mempty <> x == x`・`x <> mempty == x`|`join . return == id`・`join . fmap return == id`|

  等式を実際に評価して一致を見せる（検証項目）。
  - **可換図式を描く**（決定事項 2。図を使うことが確定している箇所）。
    `join . join == join . fmap join` を、`m (m (m a))` から `m a` への 2 つの経路として
    示す。3 節の四角形と同じ読み方（どちらの経路でも同じ）になるよう形を揃える。
    - 単位律 $\mu \circ T\eta = \mathrm{id} = \mu \circ \eta T$ の三角形も足すか
      検討する（上記「可換図式を使う箇所」の候補）。四角形と対で置くと収まりが良い。
- **`## 一文を読み解く`**: 「自己関手の圏」＝ 対象が自己関手、射が自然変換の圏。
  「モノイド対象」＝ その圏で `<>` と `mempty` にあたる射（μ と η）を持ち、
  モノイド則を満たすもの。**2 節の自己関手・3 節の自然変換・14 回のモノイドが
  ここで全部使われる。**
- ⚠ **ジョークとして消費しない。** この一文は「何を言っているか分からない例」として
  引用されがちだが、20 回は**分解して意味を通す**のが目的。茶化さない。
- ⚠ **出典を裏取りする**（下記「参考文献」）。記憶で経緯を書かない。

### 6. `# 随伴と自由生成`

**16 回 `# 「自由」とは何か` 末尾の `:::message` の回収。**
あそこには既に「忘却関手の左随伴」と書いてあり、**20 回で説明すると予告した形になっている。**

- **`## 忘却関手`**: モノイドから中身の集合だけを取り出す対応。構造を忘れるので「忘却」。
- **`## 自由関手`**: その逆向きに、集合からリスト（自由モノイド）を作る対応。
  **この 2 つが随伴の関係にある**、というのが「自由」の正確な意味。
- **`## 普遍性`**: 随伴が持つ性質を、Haskell の関数の形で見せる。
  - 集合 `a` からモノイド `m` への関数 `a -> m` を 1 つ与えると、
    `[a] -> m` が**一意に決まる**。それが `foldMap`。
  - 命令の型 `f` からモナド `m` への自然変換 `f ~> m` を 1 つ与えると、
    `Free f a -> m a` が**一意に決まる**。それが 16 回の `foldFree`。
  - **この 2 つを並べて見せるのがこの節の核心。**

  ```hs
  foldMap  :: Monoid m => (a -> m)  -> [a]      -> m
  foldFree :: Monad  m => (f ~> m)  -> Free f a -> m a
  ```

- 16 回の `foldFree` を再実装して実際に動かす（検証項目）。
- ⚠ **随伴の一般定義には踏み込まない**（決定事項 10・17）。
  上記の「1 つ与えると一意に決まる」がその内容そのものなので、そこで止める。
  $F \dashv G$ という記号だけ示し、`foldMap`／`foldFree` の 2 つの型を並べた形が
  その現れだと述べるに留める。**同型の展開も証明もしない。**

### 7. `# 米田の補題`

**17 回 `## 継続を命令の型から外す` の回収。**
あの節で `Program` に `Functor instr =>` 制約が要らなかった理由が、ここで判明する。

- **`## Coyoneda`**: 17 回の `:>>=` と同じ形の型を自作する。

  ```hs
  data Coyoneda f a = forall b. Coyoneda (f b) (b -> a)
  ```

  ```hs
  (:>>=) :: instr b -> (b -> Program instr a) -> Program instr a  -- 17 回
  ```

  **「容れ物と、中身を変換する関数」の組**という形が共通している。
- **`instance Functor (Coyoneda f)` は `f` に何も要求しない。** `fmap` は
  後ろの関数を合成するだけで済む。**これが 17 回で `Functor` インスタンスが
  不要だった理由。** 任意の型構築子を `Functor` にしてしまう構成になっている。

  ```hs
  instance Functor (Coyoneda f) where
      fmap h (Coyoneda fb g) = Coyoneda fb (h . g)
  ```

- **`lowerCoyoneda` にだけ `Functor f` が要る。** 包むのは無条件、
  取り出すときに初めて必要になる、という非対称を見せる。
- **`## Yoneda`**: 向きを逆にした型（決定事項 11。ここまで書く）。

  ```hs
  newtype Yoneda f a = Yoneda (forall b. (a -> b) -> f b)
  ```

  `liftYoneda`／`lowerYoneda` が相互に逆であること（往復すると元に戻ること）を
  コードで確かめる（検証項目）。**`forall b. (a -> b) -> f b` と `f a` が
  同じ情報を持つ**というのが米田の補題の Haskell 版。
- ⚠ **補題の一般形 $\mathrm{Nat}(\mathrm{Hom}(a, -), F) \cong F a$ は形だけ示す**
  （決定事項 8・17）。上の往復がその Haskell 版だと述べるに留め、
  $\mathrm{Nat}$・$\mathrm{Hom}$ が何であるかを最小限説明したら、**証明はしない。**
  「なぜ成り立つのか」は本格的な本に譲る（書名は挙げない。決定事項 17）。
- `Data.Functor.Coyoneda`・`Data.Functor.Yoneda` が kan-extensions パッケージにあることを
  紹介する（コードは載せない。決定事項 3）。

## 数式を使う箇所

決定事項 16。**Haskell のコードで書くと不自然になるもの**を数式にする。
判断基準は「Haskell の値・関数として書けるかどうか」。
書けるものはコード、書けないもの（対象と射のレベルの話、同型）は数式。

|節|数式|コード側の対応|
|---|---|---|
|1|結合律 $(f \circ g) \circ h = f \circ (g \circ h)$、単位律 $\mathrm{id} \circ f = f = f \circ \mathrm{id}$|`Category` の `.`・`id`、一点圏で実際に評価|
|2|関手則 $F(f \circ g) = F(f) \circ F(g)$、$F(\mathrm{id}) = \mathrm{id}$|`fmap (f . g) == fmap f . fmap g`|
|2|関手が対象 $a$ を $F a$ に、射 $f : a \to b$ を $F(f) : F a \to F b$ に移すこと|型構築子の適用と `fmap`|
|3|成分 $\alpha_a : F a \to G a$、自然性 $G(h) \circ \alpha_a = \alpha_b \circ F(h)$|`fmap h . alpha == alpha . fmap h`（＋ 可換図式）|
|4|Kleisli 圏の射 $a \to m\,b$ と合成 $\circ_{\mathrm{K}}$|`Kleisli`・`>=>`|
|5|$\mu : T \circ T \Rightarrow T$、$\eta : \mathrm{Id} \Rightarrow T$|`join`・`return`|
|5|$\mu \circ T\mu = \mu \circ \mu T$、$\mu \circ T\eta = \mathrm{id} = \mu \circ \eta T$|モノイド則の等式（＋ 可換図式）|
|6|随伴 $F \dashv G$ の記号|`foldMap`／`foldFree` の型の並置|
|7|$\mathrm{Nat}(\mathrm{Hom}(a, -), F) \cong F a$|`Yoneda` の往復|

- ⚠ **決定事項 10・11 の「立ち入らない」は数式でも同じ。** 上の表の 6・7 は
  **形を 1 つ示して名前を与えるだけ**で、展開も証明もしない（決定事項 17）。
  数式で書けることと踏み込むことは別。
- ⚠ **添字（$\alpha_a$ のような成分の書き方）は 3 節で 1 度だけ説明する。**
  Haskell では `forall a.` に隠れて見えないものなので、初出時に対応を述べる。
- ⚠ **$\Rightarrow$（自然変換）と $\to$（射）を書き分ける。** 記事内で一貫させる。
  Haskell 側では両方とも `->` になってしまうので、そこも一言添える。
- 圏の名前は $\mathbf{Hask}$ のように太字（`\mathbf`）で書く。
